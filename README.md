# 东方题材游戏场景 Midjourney Skill

这是一个用于创作**以中国文化为核心的东方题材游戏纯环境画面**的 Codex Skill。它把用户给出的主题转成一组可以直接交给 Midjourney 的中英文提示词：先尊重题材自身的空间、材料和视觉逻辑，再联想到值得探索的地点，并为每个地点设计镜头、构图、氛围和光影。

题材范围不止武侠，也包括仙侠与修仙、山海经、西游与封神、聊斋志怪、百妖夜行、地府、中式克苏鲁、民俗恐怖、苗疆巫蛊、傩文化、佛道神话、敦煌、古蜀幻想、宋韵与盛唐、东方废土、赛博东方、蒸汽朋克、机关术、海洋神话和梦境水墨。具体类型与环境表达见[题材场景映射](references/oriental-genre-map.md)。

目标不是堆叠古风符号，也不把宏大或写实当成唯一方向；场景尺度和空间规则由用户指定的题材决定。室内的一张桌子、街边的摊位、一段崖壁木桥、巨型神殿或梦境山海，都可以成为画面主体。提示词通过明确的场景、摄影机位置和画面组织来获得游戏 CG 的视觉完成度。

## 适用范围

- 东方历史生活、武侠仙侠、神话、志怪民俗、宗教幻想、东方奇幻与科幻等游戏环境场景。
- 用户提供一个主题，希望联想到同一题材范围内功能、地理、生活、信仰或交通相关的其他地点。
- 为已有场景设计更有辨识度的取景、构图、光线和氛围。
- 用户明确要求时，分析游戏场景参考并提炼可迁移的视觉方法。

本 Skill 只负责**纯环境场景提示词**，默认不出现人物；不编写剧情，也不会自动生成图片。

## 使用方法

在 Codex 对话中调用 `$midjourney-wuxia-environments`，然后说明题材、场景主题、数量和必要限制。当前调用名沿用已有 Skill 标识；Skill 的适用范围已扩展到东方题材游戏场景。主题明确时，默认从它出发做合理的地点联想；不需要先确认是否扩展，也不编造一段世界观故事。

维护项目时，将本仓库作为独立项目打开。普通提示词生成直接调用 Skill。响应速度还受当前聊天的模型与思考强度影响；Skill 文件不会改变这些设置，全局默认值也不代表已有聊天当前采用的值。

```text
使用 $midjourney-wuxia-environments，宗门，给我 8 组场景提示词。
```

```text
使用 $midjourney-wuxia-environments，街道，给我 6 组场景；联想到酒楼、客栈、摊贩或刀匠铺等街区生活空间。
```

```text
使用 $midjourney-wuxia-environments，给我 5 组雪地场景，避免宏大远景，多用近景和中景。
```

```text
使用 $midjourney-wuxia-environments，山海经上古异兽题材，给我 6 组纯环境场景，以神山、部落遗址和异兽栖域为联想方向。
```

```text
使用 $midjourney-wuxia-environments，聊斋志怪与宋韵市井融合，给我 5 组场景；以空置街巷和庭院表现诡异感，不出现人物。
```

```text
使用 $midjourney-wuxia-environments，赛博东方机关城，给我 8 组场景，保留古典城市空间与未来机械的对照。
```

没有提供主题时，Skill 会通过一个选项问题确认方向，默认展示下方的 12 个常用题材及“随机探索”；也支持直接输入完整目录中的其他题材或具体地点。支持选项交互时可点击选择，否则回复编号或文字。收到实际选择后直接生成，保留已给出的数量与限制，不追加细分问题。主题已明确或用户已要求随机时，直接开始。

## 默认生成规则

- **数量**：每次默认 10 组；用户明确指定其他数量时按指定数量生成。
- **题材优先**：用户给出的题材决定空间、材质、生活设施、神异现象、技术规则和总体气质。不默认把不同题材混在一起；只有用户提出融合时才结合指定类型。
- **联想方式**：以用户主题为起点，扩展到题材范围内合理相关的地点。关联可以来自地理、生活、信仰、营生、技术或通行功能；每个场景独立成立，不必写成连续故事或重复主题标志物。
- **纯场景**：默认不出现人物。用建筑、门窗、道路、桥梁、树木或地形体现空间尺度。
- **画面信息**：每条提示词围绕一个明确主体，只保留必要环境锚点；不确定的设施或空间关系宁可删去，也不臆造补全。
- **空间规则**：室内、室外或过渡空间按场景自然表达，不使用固定前缀。历史生活空间保持可理解、可使用；神话、仙侠、梦境或异文明可以超现实、巨构，但仍要让空间关系可读。
- **镜头与画面**：根据场景变化选择景别、机位和观看路径，不默认平视、正面、中轴对称或完整展示建筑。
- **氛围与光影**：明确视觉焦点及亮暗关系，让光线参与构图，不让整个画面平均发亮。
- **东方意境**：通过藏露、虚实、疏密、远近、动静、明暗和留白建立；不靠古风物件或符号堆叠。
- **环境叙事**：通过空间状态、时间天气、使用痕迹和自然侵蚀形成联想，不用套路道具解释剧情。
- **限制词**：默认无人、无可读文字、无水印；其他限制随题材设置。历史空间可排除现代物件，赛博与科幻保留相应技术，避免限制词否定场景本身。

## 输出格式

先在代码块外列出编号场景名，再提供中文与英文两个合并代码块。两种语言按同一场景顺序排列，以空行分隔；代码块中只放提示词，不放名称、编号或解释。英文忠实对应中文的物件、空间、镜头和光线，不重新设计画面。

每条提示词包含以下画面要素，但会按场景自然组织，不机械拼装固定模板：

> 主体 + 场景 + 镜头 + 构图 + 氛围 + 光影 + 必要限制词

镜头、构图、氛围和光影是必需的；无助于识别主体、组织画面或建立氛围的形容词和陈设会删去。Skill 不会为了显得“游戏 CG”而机械添加 `epic`、`AAA`、`monumental` 等标签。

## 项目文件

```text
.
├── AGENTS.md                        # 区分提示词生成与项目维护
├── SKILL.md                         # 生成流程、画面规则与输出自检
├── agents/openai.yaml               # Skill 展示信息和默认调用说明
└── references/
    ├── game-reference-study.md      # 游戏场景参考分析
    ├── oriental-genre-map.md        # 东方题材到环境空间的映射
    └── scene-library.md             # 可按需查阅的场景灵感
```

常规生成直接使用主 Skill：定场景 → 写中文 → 对应英文 → 一次自检。不会因题材宽泛而遍历资料，也不触发项目检查或联网研究；同一对话中已读且未更新的资料直接复用。题材陌生、需要环境落点时，只查题材映射的相关部分；用户要求参考研究时再读取对应资料。

## 自检

输出前集中检查一次：题材与物件用途、空间与机位、镜头／构图／氛围／光影、双语一致性，以及整批是否重复。发现问题只修对应部分，不确定的设施或关系直接删除，并同步两种语言。末尾提供一句简短检查结论。

将仓库放入 Codex 的个人 Skills 目录，然后在新对话中调用：

```bash
git clone https://github.com/2053197099/midjourney-wuxia-environments.git ~/.codex/skills/midjourney-wuxia-environments
```

如果仓库设为私有，先确保当前 Git 环境已登录有权限的 GitHub 账号。安装路径已有同名目录时，不要覆盖；先备份或选择合适的 Skills 目录，再安装。
